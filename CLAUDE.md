# Job Search Alerts — repo guide

Task Scheduler "JobSearch Daily" (Mon–Fri 05:45, 90-min limit) → `scheduler/run.ps1` → `python -m jobsearch.run`.
Collect (Python) → filter → headless `claude -p` ranks in `data\runs\<date>\` → Gmail SMTP digest.
"Late" (banner in the digest) = run started after 06:30, i.e. the PC missed 05:45. Never set for a `--date` run or a `--no-send` preview.

## Privacy (hard rules)
- `C:\JobSearch\data\` holds the owner profile, the real exclusion list, `.env` (Gmail app password), the DB, logs. **Never commit it or copy it into the repo.** The job search is confidential.
- Never echo `.env` values into chat or logs.
- Real exclusion list: `C:\JobSearch\data\config\exclusions.yaml`. `config/exclusions.example.yaml` is only a format example.

## Operations
- Tests: `.venv/Scripts/python -m pytest -q` (live network tests: `-m live`). Tests use `tmp_path`, never `data\`.
- Source smoke test: `.venv/Scripts/python -m jobsearch.collect --dry-run --window-hours 72 [--source jobspy]`
- Preview without sending: `python -m jobsearch.run --no-send --force` → writes everything (candidates, ranked.json, stats, `digest.preview.{html,txt,subject.txt}`) to `runs\<date>-preview\`. The real `runs\<date>\` folder and its resend files are never touched by a preview. Preview folders are pruned after 60 days like the rest.
- Application watch: private `data\config\watch.yaml` (format: `config/watch.example.yaml`) lists postings you applied to (greenhouse/lever/ashby board + job id). Every run (also zero-candidate and degraded days) checks them (`jobsearch/watch.py`), records `watch_status` in the DB (`closed_on` = first day seen closed; unknown checks change nothing) and shows a "Your applications" block at the top of the digest (still open / POSTING CLOSED on <date> / status unknown). Failures only add a digest warning.
- Logs: `data\logs\<date>.log` (30 days), scheduler stdout/stderr: `data\logs\task-stdout.log` (UTF-8). Run artifacts: `data\runs\<date>\` (60 days).
- The task runs hidden (`-NonInteractive -WindowStyle Hidden`), and under S4U there is no desktop session, so **crash toasts are invisible: the crash/failure email is the signal.**
- Don't run two at once: `data\run.lock` makes a second run exit 4 (log: "another run holds the lock; skipped").
- The task has two triggers: Mon–Fri 05:45 and "at logon" (3-min delay). It runs as Interactive (only when the owner is logged on), so an overnight reboot that signs the owner out skips the 05:45 trigger (happened 2026-10-15); the logon trigger then sends the digest, late-bannered, at the next sign-in. The action passes `--weekdays-only` so a weekend logon sends nothing (`--force` overrides).
- S4U auth check (does `claude` still authenticate with no interactive logon?): always run it with a PAST `--date` (e.g. last Sunday), **never a future date**. Research-cache rows dated in the future never expire. If it happens, purge them: `DELETE FROM company_research WHERE researched > date('now')`.

## Run outcome
- Exit codes: 0 ok / already sent, 2 send failed, 3 crashed (crash email with no job data; the toast only shows in an interactive session), 4 skipped because another run holds the lock. `run.ps1` itself exits 1 when the venv python is missing (`python missing: <path>` is appended to `task-stdout.log`).
- Time budget: whole run 80 min (task limit 90). Collection soft-stops after 40 min (remaining sources skipped, warning in the digest). Ranker timeout = `min(configured, 80 - elapsed - 8 min send reserve)`; with under 5 min left, ranking is skipped and the unranked list is sent (those jobs are not marked sent). The collection deadline is also honored inside JobSpy (before each search), between ATS boards and between board queries; after 2 consecutive failed searches on a site, JobSpy waits `breaker_cooldown_s` (90 s) and retries one term; if that fails too it skips the site's remaining terms (digest warning). LinkedIn is two-phase: searches run without descriptions, then job pages are fetched (`LinkedIn._fetch_details`, private but test-guarded) only for title-passing, not-yet-emailed rows, at most `max_detail_fetches` (40) per run, stopping after 3 consecutive failed fetches. Per-source seconds are logged (`source jobspy: 350 jobs in 1832 s`) and shown in the footer.
- Candidates the ranker omitted or returned invalid appear under "Unranked (ranker omitted or invalid)" and are not marked sent (they retry tomorrow). Dealbreaker jobs are listed compactly in the footer for supervision.
- A missing `data\config\exclusions.yaml` adds "exclusions file missing ... NOT applied" to the digest warnings.
- Run statuses in the DB: `sent`; `sent_degraded` (every source failed; does NOT count as sent, a rerun redoes it); `send_failed` (a plain rerun resends the saved digest instead of recollecting); `crashed`.
- After missed days the collection window widens to days-since-last-send, capped at 168h.

## Filtering and ranking
- Staffing firms not on the named list are caught by a company-name pattern heuristic (`Exclusions.match` -> "staffing agency (name pattern)"): defaults in `exclusions.STAFFING_NAME_PATTERNS`, extend via optional `staffing_name_patterns:` in the private `exclusions.yaml`; names containing "holdings" are exempt.
- Description-derived rules (degree, clearance, residency, contract wording) only FLAG; the ranker adjudicates dealbreakers. Title/structured-field rules still drop.
- Work travel: title/location stating travel ("25% travel", "travel required") drops (`work travel (title/location)`); description travel sentences only add `travel: "<snippet>"` flags (`filters.travel_mentions`) and the ranker decides. Company offsites/summits 1-2x/year are allowed (ranker adds an `offsite:` gap).
- On-call: title/location stating it ("(On-Call)", "on-call rotation", "24/7 on-call") drops (`on-call (title/location)`); description wording only adds `on-call: "<snippet>"` flags (`filters.oncall_mentions`, negations skipped). A required rotation is a ranker DEALBREAKER; occasional after-hours help is only a gap.
- Staffing agencies / reposting platforms that slip past the exclusion list are a ranker DEALBREAKER (anonymized employer or talent marketplace).
- Degree: `filters.degree_mentions` adds `degree: "<snippet>"` flags ("MS"/"BS" only next to degree words). The ranker returns a `degree` object per job (`rank.DegreeInfo`; an invalid one is dropped to None, never the job). Every digest card/row shows a degree line; with no object it falls back to the first `degree:` flag.
- Pay target: private `data\config\owner.yaml` (`current_base_salary`, `min_raise_pct` default 25) -> `config.pay_target` = max(`salary_floor`, base x (1 + pct/100)); floor only if the file is missing/invalid. The digest moves jobs whose pay midpoint (stated salary first, else the ranker's `pay_min`/`pay_max`) is below it to a footer "Below pay target" list (still marked sent; unknown pay is kept). Never print the base. The ranker receives the target in its task line and reads `data\profile\ranker-profile.md` (no name, employer names or base salary — mirror skill/priority changes there; the full `personal-profile.md` is only a fallback with a warning). Python renders the "+X% to +Y% vs current base" text from the ranker's `pay_min`/`pay_max`.
- Python computes the final score from `role_type` + `score_parts` (never trust the model's own total). `app_dev`/`other` roles cap skills at 15; a DEALBREAKER gap forces score 0. DEALBREAKER gaps use canonical keys (`travel`, `on-call`, `onsite`, `clearance`, `degree`, `contract`, `staffing`, `residency`); the footer groups them by key.
- Pass B research only covers jobs that will be shown (score ≥ 75, no dealbreaker, not `app_dev`/`other`, pay midpoint ≥ target), at most 8 new companies per run; `Confirmed` may come from authoritative search snippets (levels.fyi, glassdoor, indeed, comparably, builtin, the company's own page). Descriptions handed to the ranker are trimmed by `rank.trim_description` (EEO/boilerplate paragraphs dropped, pay text always kept, requirements window preferred) to `description_chars` 6000. Cards hide the `degree:`/`travel:`/`on-call:` snippet flags; unknown benefit rows collapse into one "No public data" line.
- Ranker lock-down: `scheduler/ranker-settings.json` (allow/deny rules) plus flags from `jobsearch/rank.build_command` (`--permission-mode dontAsk`, `--safe-mode`, `--tools` allowlist, `--strict-mcp-config`, `--setting-sources project`, no session persistence). **Never use `--bare`** (it disables subscription auth). WebFetch is limited to a domain allowlist in `ranker-settings.json` (glassdoor, indeed, levels.fyi, comparably, builtin, teamblind, layoffs.fyi, linkedin, crunchbase) — probe-verified 2026-10-15. `--max-budget-usd 8` caps a run (subtype `error_max_budget_usd` is an early stop: a ranked.json already written is kept).
- After any Claude Code upgrade, re-run the lock-down probe in `docs/lockdown-probe.md` using the current `build_command` argv, and confirm Bash/PowerShell, MCP, reads of `data\` secrets and out-of-folder writes are still denied.
- The CLI must be logged in: check `claude auth status`. Path comes from `rank.resolve_claude_exe` (config `ranker.claude_exe`, an `%APPDATA%\npm\...\claude.exe` path; never a `.cmd` shim).

## Gotchas
- python-jobspy 1.3.0 installs normally (it brings `curl_cffi`); `fetch_description` replaced `linkedin_fetch_description`. LinkedIn's logged-out search ignores `is_remote`/`job_type` (the "not remote" filter does that work), so those are sent to Indeed only.
- Free-text mention scanners (travel, on-call, degree, clearance, education, contract, office) live in `jobsearch/mentions.py` behind one `clause_mentions` helper; `filters.py` re-exports them.
- ZipRecruiter (403) and Google (0 rows) are dead in JobSpy as of 2026-09-29, so only linkedin+indeed are used.
- `run.ps1` runs under Windows PowerShell 5.1: native stderr must not hit `$ErrorActionPreference = "Stop"`.
- The task's RestartCount only retries when the task fails to launch, not on a non-zero exit; rerun by hand (a plain rerun resends a saved digest after a send failure).
